# UX-SOCIAL-UI-001 — تجربة اجتماعية موثوقة وحسابات احترافية

## 1. عقد التجربة

هذه مواصفة تفاعل منخفضة الدقة وليست تعريفًا للتوكنز أو المظهر. تستعير ألفة نموذج الشبكات
الاجتماعية (رأس ثابت، تغذية وسطية، جانبان، ناشر وبطاقات تفاعل) مع هوية «بصيرة» الأصلية؛ لا أصول
أو نصوص أو نسب أو علامات Facebook. العربية وRTL هما الأصل. البيئة mock داخلية مقيدة وليست حماية
إنتاجية، و«اطرح سؤالًا» هو الإجراء الرئيسي.

الأولوية داخل المحتوى: المؤلف ← التوثيق والتخصص ← النص والمصادر ← الخلاف المعتبر ← التفاعل.
الخاص لا يُخفى شكليًا؛ لا يظهر في DOM أو URL أو telemetry خارج سطحه المصرح.

## 2. خريطة الموقع والتنقل

| المسار | H1 | الوصول |
|---|---|---|
| `/` | أحدث المعرفة | عام/مخصص للعضو |
| `/explore`, `/search` | استكشف الموضوعات / نتائج البحث | عام |
| `/content/:id`, `/scholars/:id` | عنوان المحتوى / اسم العالم | حسب السياسة |
| `/saved`, `/profile` | المحفوظات / ملفي | عضو |
| `/login`, `/register` | تسجيل الدخول / إنشاء حساب | زائر |
| `/verify-email` | تحقق من بريدك | تسجيل حديث |
| `/forgot-password`, `/reset-password` | استعادة كلمة المرور / تعيين كلمة مرور جديدة | زائر/رابط صالح |
| `/onboarding/interests`, `/onboarding/profile` | اختر اهتماماتك / أكمل ملفك | عضو جديد |
| `/account-review` | مراجعة الحساب | حساب موقوف |

ترتيب DOM: رابط التخطي، header، navigation، main، complementary، footer. ويتبع Tab هذا الترتيب لا
موضع CSS. التنقل: الرئيسية، استكشف، البحث، اسأل، المحفوظات، ملفي. الحالي يحمل `aria-current=page`
واسمًا مرئيًا، ولا يعتمد على اللون وحده.

- `>=1200`: رأس ثابت، تنقل يمين، feed وسط، سياق يسار.
- `1024–1199`: تنقل يمين + feed؛ ينتقل السياق إلى sheet بعنوان «استكشف المزيد».
- `768–1023`: feed واحد، وزران منفصلان يفتحان sheet التنقل والسياق من البداية المنطقية (اليمين).
- `<768`: رأس مدمج وتنقل سفلي ثابت بخمسة عناصر: الرئيسية، استكشف، اسأل، المحفوظات، ملفي. البحث
  في الرأس. padding سفلي يمنع حجب آخر محتوى، مع safe-area وأهداف لمس 44×44px.
- عند 200% zoom يعاد التدفق إلى عمود واحد إن لزم، بلا تمرير أفقي عام أو فقد وظيفة.

## 3. Wireframes التغذية

### سطح المكتب 1280–1440

```text
┌──── header: العلامة | البحث الشامل | بيئة تجريبية | إشعارات | الحساب ────┐
│ تنقل يمين     │ main: أحدث المعرفة                    │ سياق يسار      │
│ الرئيسية حالي │ Topic Highlights                     │ موضوعات مقترحة │
│ استكشف/بحث    │ composer + مرشحات لك/تتابعهم/الأحدث  │ علماء موثقون   │
│ اسأل/محفوظات  │ بطاقة محتوى                          │ اكتمال الملف   │
│ ملفي          │ بطاقة محتوى + متابعة/تحميل المزيد    │                │
└───────────────┴───────────────────────────────────────┴────────────────┘
```

main هو الأعلى بروزًا والأعرض. الجانبان sticky دون حجب نهاية الصفحة. إذا غاب السياق يتمدد main ضمن
حد قراءة مريح ولا يبقى عمود فارغ. `Topic Highlights` موضوعات دائمة منتقاة لا Stories: رمز أصلي، اسم،
متابعة/تتابعه؛ بلا مدة أو autoplay أو عداد مشاهدة أو ring يوحي بالانتهاء. tabs تستخدم الأسهم وHome/
End ثم Enter/Space، ولا تنقل التركيز إلى panel دون طلب.

### الهاتف 360–390

```text
┌ العلامة                              بحث | إشعارات ┐
│ H1 أحدث المعرفة                                   │
│ [موضوعات منتقاة ← صف أفقي + السابق/التالي]        │
│ [ما السؤال الذي تبحث له عن جواب موثوق؟] [اسأل]    │
│ [لك] [تتابعهم] [الأحدث]                           │
│ بطاقة محتوى بعرض واحد، والأفعال تلتف عند الحاجة   │
├ الرئيسية | استكشف | اسأل | المحفوظات | ملفي ─────┤
```

لا توجد rails في DOM المرئي؛ تظهر في sheet مسمى. الصف الأفقي يدعم scroll-snap اختياريًا وزري لوحة
مفاتيح «السابق/التالي». الناشر full-screen sheet أو صفحة، مع حفظ المسودة.

## 4. الناشر وبطاقة المحتوى

### الناشر

المطوي: صورة آمنة، «ما السؤال الذي تبحث له عن جواب موثوق؟»، «اطرح سؤالًا». عند الفتح يكون ترتيب
التركيز: عنوان السطح، عام/خاص مع شرح الجمهور، العنوان، التفاصيل، الموضوع، الخصوصية، إخفاء الاسم،
الأسئلة المشابهة، المراجعة، الإرسال. combobox يدعم الأسهم/Enter/Escape.

يظهر `status` «حُفظت المسودة». الإغلاق مع تغييرات يطلب «متابعة التحرير» أو «تجاهل المسودة»؛ Escape
يغلق أعلى سطح فقط ثم يعيد التركيز للمشغّل. أثناء الإرسال: زر disabled ونص «جارٍ الإرسال…». عند
offline/session expired/409 تبقى القيم ولا retry تلقائيًا. النجاح يظهر بعد استجابة mock مؤكدة داخل
الصفحة، مع رابط السؤال ونسخة «هذه بيئة تجريبية».

### بطاقة المحتوى

ترتيب DOM:

1. صورة، اسم المؤلف، شارة توثيق قابلة للتركيز وشرح «تم التحقق من الهوية والمؤهلات المحددة»، التخصص،
   وقت التحديث، قائمة الإجراءات.
2. النوع والموضوع، العنوان والملخص.
3. صندوق المصادر ظاهر؛ المصدر الأول ثم disclosure «عرض كل المصادر (3)».
4. عند الخلاف: «آراء معتبرة» مرتبة تحريريًا بالتوازي، بلا فائز أو تصويت أو رقم شعبية.
5. مفيد، حفظ، مشاركة للمحتوى العام فقط، تعقيب، إبلاغ؛ ثم preview للتعقيبات.

«مفيد» و«حفظ» toggle بـ`aria-pressed` وأسماء حالة («إلغاء مفيد»، «إزالة من المحفوظات»). أثناء الطلب
يمنع duplicate. الفشل يعيد الحالة والعدد ويعلن «تعذر الإجراء؛ عادت الحالة السابقة». الخاص لا يرندر
زر مشاركة ولا payload خاصًا.

### التعقيبات

الاسم «تعقيبات علمية وطلبات توضيح»، لا دردشة. يختار العضو: طلب توضيح/إضافة مصدر/ملاحظة منهجية، ثم
نص وإرسال؛ الإبلاغ متاح. غير الموثق لا يرى أداة «فتوى/إجابة شرعية». الترتيب تحريري/زمني معلن، لا
بالشعبية. empty: «لا توجد تعقيبات بعد» وإجراء واحد إن سمحت السياسة.

## 5. حالات feed

| الحالة | المواصفة |
|---|---|
| loading | skeleton ثابت يحاكي highlight/composer/بطاقتين، `aria-busy` واسم مهمة؛ بلا shimmer |
| empty | سبب مرتبط بالمرشح + إجراء واحد «استكشف موضوعات» |
| server error | رسالة غير تقنية + retry للعمل idempotent + مرجع دعم إن وجد |
| offline | banner غير حاجب؛ cached قراءة فقط، mutations معطلة والمسودة محفوظة |
| success | تأكيد inline وlive region؛ ليس toast وحده للعمل المهم |
| forbidden | يشرح الممكن دون كشف وجود مورد خاص |
| session expired | login؛ يحفظ المسودة غير الحساسة ويستعيدها بعد session mock مؤكدة |

## 6. غلاف الحساب responsive

desktop `>=1024`: منطقتان؛ جهة البداية تحمل العلامة ووعد «انضم إلى معرفة موثقة» وثلاث نقاط ثقة،
والأخرى بطاقة نموذج واحدة. لا feed خلفها ولا شهادات زائفة. tablet: شريط تعريف مختصر فوق البطاقة.
mobile/200%: عمود واحد، العلامة والوعد ثم النموذج مباشرة، والروابط القانونية بعد الإجراء الثانوي.
النموذج 100% عند 360px.

landmarks: skip link، header صغير، main وH1 واحد، form مسمى، footer للشروط والخصوصية والمساعدة
والعودة للاستكشاف. لا يتحرك focus تلقائيًا أثناء الكتابة.

## 7. تدفقات الحساب

### `/login`

ملخص أخطاء بعد submit؛ بريد label ثابت و`autocomplete=email`؛ كلمة مرور و`current-password`؛ زر إظهار/
إخفاء باسم حالته؛ النسيان؛ تذكرني فقط إن دعمه العقد؛ «تسجيل الدخول»؛ «إنشاء حساب».

- Enter يرسل مرة؛ الزر disabled و«جارٍ تسجيل الدخول…» و`aria-busy`.
- invalid/unknown لهما نفس النص: «تعذر تسجيل الدخول. راجع البيانات أو أعد المحاولة».
- 429: «محاولات كثيرة. انتظر قليلًا ثم أعد المحاولة». offline يحتفظ بالبريد فقط، لا كلمة المرور.
- النجاح ينتظر session mock ثم مسارًا داخليًا allow-listed أو `/`، ولا redirect خارجي.
- الموقوف إلى `/account-review`: وصف عام ومسار مراجعة/تواصل وتسجيل خروج فقط.

### `/register`

الحقول: الاسم المعروض، البريد، كلمة المرور، تأكيدها، checkbox موافقة صريحة وروابط، ثم «إنشاء حساب
عضو». لا اختيار عالم/مشرف أو توثيق. متطلبات كلمة المرور قبل الإدخال: 12 محرفًا على الأقل في mock،
وتتحدث نصيًا؛ اللصق ومدير كلمات المرور مسموحان.

التحقق بعد blur وsubmit. كل خطأ inline مع `aria-describedby` وفي ملخص قابل للتركيز؛ روابط الملخص تركز
الحقول ولا تمسح القيم السليمة. عدم التطابق عند التأكيد. loading يمنع duplicate. النجاح المؤكد إلى
`/verify-email` ببريد masked مثل `m***@example.com`.

### `/verify-email`

«إذا أمكن إنشاء الحساب، أرسلنا تعليمات التحقق إلى m***@example.com». إعادة الإرسال disabled مع
«يمكن إعادة الإرسال بعد 45 ثانية»، ثم تتاح؛ 429/offline منفصلان. تغيير البريد يعيد الاسم والبريد فقط
إلى التسجيل بلا كلمات مرور. نجاح mock يقدم «متابعة الإعداد».

### `/forgot-password`

بريد و«إرسال تعليمات الاستعادة». النتيجة نفسها دائمًا: «إن وُجد حساب بهذا البريد، ستصل تعليمات
الاستعادة». loading يمنع التكرار؛ offline يحتفظ بالبريد؛ 429 مستقل؛ لا account enumeration.

### `/reset-password`

يُستهلك token قبل render ولا يدخل analytics أو رابطًا منسوخًا. الحالات: صالح يعرض كلمة جديدة وتأكيدها؛
منتهي «اطلب رابطًا جديدًا»؛ مستخدم «استُخدم الرابط» مع login/طلب جديد؛ غير صالح رسالة عامة وطلب جديد.
النجاح المؤكد: «تم تحديث كلمة المرور في البيئة التجريبية» ثم login، مع توضيح أن إبطال الجلسات محاكاة.

### Onboarding

«الخطوة 1 من 2» نصيًا، رجوع، «حفظ ومتابعة»، «تخطي الآن». الأولى تختار 3–7 موضوعات عبر checkboxes
وتعلن العدد؛ يمكن التخطي صراحة. متابعة العلماء اختيارية ومرتبة أبجديًا/تحريريًا لا بالشعبية. الثانية:
صورة اختيارية، نبذة، خصوصية أساسية. تحفظ كل خطوة mock، والعودة تستعيد القيم. الإكمال إلى feed مع
تأكيد inline/live غير حاجب.

## 8. الوصول ولوحة المفاتيح والحركة

- أول submit غير صالح يركز ملخص الأخطاء؛ روابطه تركز الحقول. لا focus jump مع inline validation.
- dialog/sheet يحصر التركيز، يبدأ بالعنوان/أول حقل، Escape يغلق إن لم توجد مسودة، ويعيد التركيز.
- tabs/combobox/dropdown تتبع WAI-ARIA؛ tooltip يعمل بالتركيز وhover ويغلق بـEscape.
- الأخطاء بـ`aria-describedby`؛ submit error بـ`role=alert`؛ async الهادئ بـ`role=status`. لا positive
  `tabindex` أو keyboard trap. focus ظاهر ولا يعتمد على اللون وحده.
- كلمات المرور لا تحفظ في draft/state دائم/telemetry/URL. البريد وtoken والنص الحر لا يدخلون analytics.
- CSS للحالات المباشرة. Motion فقط لفتح sheet/dialog وانتقال onboarding وتأكيد toggle؛ لا تحريك كل
  بطاقة أو autoplay/parallax. `prefers-reduced-motion` يجعل الانتقال فوريًا بلا translation/scale أو
  stagger، مع نفس الوظيفة والتركيز. GSAP خارج P0؛ لا حاجة UX تبرره، ولا ملكية مشتركة مع Motion.

## 9. مصفوفة الاستجابة واختبار الاستخدام

| العرض | المتوقع |
|---:|---|
| 360/390 | عمود واحد، header مدمج، bottom nav، 44px، بلا overflow عام |
| 768 | feed واحد وsheets؛ auth عمود واحد/تعريف مختصر |
| 1024 | تنقل يمين + feed؛ السياق sheet؛ auth منطقتان إن بقي مقروءًا |
| 1280/1440 | ثلاثة أعمدة، feed أعلى بروزًا، rails مستقلة |
| 200% zoom | reflow مناسب بلا فقد إجراء أو تمرير أفقي للصفحة |

سيناريوهات الاختبار: login بالكيبورد؛ خطأ اعتماد عام؛ register وثلاثة أخطاء؛ forgot دون كشف الحساب؛
إكمال/تخطي onboarding؛ استعادة مسودة بعد offline؛ rollback للحفظ؛ شرح شارة التوثيق؛ bottom nav عند 390.

## 11. مخاطر وتسليم

- يحدد design-system-agent الهوية البصرية الأصلية؛ هذه الوثيقة لا تفرض token أو مكتبة.
- يجب الحفاظ على DOM order حتى عند تغيير CSS layout.
- سياسة التعقيبات، مزود الهوية والبريد، session/MFA، الاحتفاظ والحذف، وترتيب feed الإنتاجي تحتاج
  حوكمة/أمن قبل الإنتاج. mock يعلن ترتيبًا تحريريًا/زمنيًا فقط.
