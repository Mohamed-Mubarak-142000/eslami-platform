# حزمة متطلبات المنتج — MVP

هذه الحزمة هي مرجع التنفيذ لمرحلة الـFrontend. عند التعارض، القرارات المعلّمة
`مطلوب اعتماد` لا تتحول إلى سياسة إنتاج قبل اعتماد صاحب المنتج والمراجع المختص.

| المهمة | المخرج |
|---|---|
| PROD-001 | [scope.md](scope.md): الوعد، النطاق، الاستبعادات، بوابات الإطلاق |
| PROD-002 | [personas-permissions.md](personas-permissions.md): الشخصيات والأدوار والصلاحيات |
| PROD-003 | [p0-requirements.md](p0-requirements.md): قصص P0 ومعايير القبول والحالات الطرفية |
| PROD-004 | [governance.md](governance.md): التوثيق والخصوصية والإشراف والخلاف |
| PROD-005 | [domain-model.md](domain-model.md): المصطلحات والكيانات والحالات والانتقالات |
| PROD-006 | [traceability.md](traceability.md): ربط القدرات بالشاشات والقصص والتحليلات |

## قواعد استخدام الحزمة

- المعرّفات ثابتة وتُستخدم في التصميم والـStorybook والاختبارات وقرارات التسليم.
- `يجب` تعني شرط قبول P0، و`ينبغي` توصية لا تمنع التسليم إلا إذا وردت في معيار قبول.
- كل شاشة تنفذ حالات `loading / empty / error / offline / forbidden` المناسبة.
- الواجهة تعكس الصلاحيات، لكن الخادم هو مصدر قرار التفويض والحالة النهائي.
- لا تُرسل نصوص الأسئلة أو الإجابات أو بيانات الوثائق إلى analytics أو error logs.
