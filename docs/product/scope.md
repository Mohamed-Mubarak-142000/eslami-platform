# PROD-001 — نطاق منصة Twister Crepes & Pizza

## الوعد والنتيجة

الاسم التشغيلي: **Twister Crepes & Pizza**. موقع طلب طعام عربي (RTL) بهوية بصرية
فاخرة وسينمائية (خلفية غامقة، لمعان أحمر/ذهبي) يمكّن الزائر من تصفح المنيو،
تخصيص الطلب (المقاس/الإضافات/درجة الحرارة)، إضافته للسلة، وإتمام الطلب عبر
رسالة واتساب جاهزة تُرسل مباشرة لصاحب المطعم — بدون حساب مستخدم وبدون بوابة
دفع إلكتروني.

النتيجة الأساسية: يصل الزائر من الصفحة الرئيسية إلى طلب واتساب مكتمل وصحيح
(بالأسعار والإضافات الصحيحة) في أقل عدد خطوات ممكن، على الموبايل أولًا.

هذا معلم **يستبدل** منصة "المنارة" الإسلامية السابقة بالكامل في نفس المستودع.
نقطة الرجوع محفوظة عبر git tag `almanara-final`.

## P0 داخل النطاق (معلم `twister-storefront-v1`)

| Capability | النتيجة المطلوبة |
|---|---|
| CAP-SHELL | Header (شعار + 6 عناصر تنقل + CTA اطلب الآن + drawer موبايل)، Footer، شاشة تحميل، سلوكيات RTL/dark |
| CAP-HERO | مشهد سينمائي (ستارة/شعار/spotlight/parallax) على الرئيسية |
| CAP-HOME | تصنيفات، الأكثر طلبًا، بانر افتتاح، لماذا نحن، مناطق التوصيل، تقييمات، إنستجرام، أسئلة شائعة، CTA |
| CAP-MENU | تبويبات تصنيف ثابتة، فلترة، بحث عربي، بطاقة منتج، معاينة سريعة |
| CAP-PRODUCT | صفحة منتج: مقاس/إضافات/حرارة/ملاحظات/كمية، سعر لحظي، منتجات ذات صلة |
| CAP-CART | سلة (drawer + صفحة): تحديث/حذف، كوبون، هدية بطاطس تلقائية، رسوم توصيل، إجمالي |
| CAP-CHECKOUT | نموذج بيانات التوصيل، توليد رسالة واتساب دقيقة، فتح `wa.me` |
| CAP-OFFERS | صفحة عروض (افتتاح كبير/بطاطس هدية/عروض الخميس) مع عداد تنازلي |
| CAP-REVIEWS | تقييمات/نجوم/عدادات متحركة |
| CAP-CONTACT | واتساب/اتصال/خريطة/مناطق/ساعات/نموذج تواصل |
| CAP-ADMIN | لوحة تحكم محلية (بدون خادم حقيقي): تسجيل دخول، CRUD لـ6 موارد، سجل طلبات، تصدير JSON |
| CAP-PWA | تثبيت، صفحة offline، manifest |
| CAP-STATES | حالات loading/empty/error/offline/closed-hours/popup-blocked لكل مسار |

## P1 مؤجل صراحة

- إشعارات push حقيقية (تحتاج VAPID + قاعدة اشتراكات + خادم إرسال) — معلم مستقل.
- خادم/قاعدة بيانات حقيقية متعددة المستخدمين للوحة التحكم — معلم `twister-backend-v1`.
- واجهة إنجليزية/تبديل لغة.
- حسابات عميل حقيقية (تسجيل دخول/تسجيل عميل) — الطلب ضيف فقط عبر واتساب.
- خريطة تفاعلية بمضلعات مناطق فعلية، فيديوهات تقييم حقيقية، فيد إنستجرام مباشر.

## خارج النطاق

- بوابات دفع إلكتروني حقيقية؛ الدفع المذكور في الواجهة نصي فقط (كاش/فودافون كاش
  عند الاستلام) ويُؤكَّد عبر واتساب، لا معالجة فعلية للبطاقات.
- تطبيقات native؛ المطلوب Web responsive عربي RTL + PWA installable.
- عرض تقييمات/تصنيفات مُصطنعة كحقيقية (انظر `reviews-policy.md`).

## قيود الإصدار

- العربية هي اللغة الوحيدة في هذا المعلم، RTL وmobile-first، هدف WCAG 2.2 AA.
- لا يوجد backend/قاعدة بيانات: البيانات seed ثابتة في `src/mocks/twister`، وأي
  تعديل إداري يُخزَّن محليًا في المتصفح (`localStorage`) + زر Export JSON.
- كل سعر/صورة/بيانات تواصل حقيقية (شعار، عنوان، هاتف، مناطق، ساعات) لم تُستلم من
  صاحب العمل بعد؛ تُعرض كـ placeholder موسوم `owner-confirm` (انظر `business-facts.md`).
- لا نجاح مرئي لإرسال الطلب قبل فتح نافذة واتساب فعليًا؛ إن حُجبت النافذة تظهر
  رابط بديل قابل للنقر.

## بوابات Go/No-Go

1. اعتماد صاحب المطعم للمنيو والأسعار النهائية (`menu-catalog.md`) وبيانات
   التواصل (`business-facts.md`).
2. اعتماد نص رسالة واتساب النهائي (`whatsapp-order-message.md`).
3. اختبارات RTL/a11y/الأداء (Lighthouse) وصفر عيوب P0 مفتوحة من `qa-agent`.
4. مراجعة أمان لوحة التحكم المحلية وتوثيق حدودها بوضوح في تقرير الإطلاق.

## قرارات غير مانعة للتصميم ومطلوب اعتمادها قبل الإنتاج

- هل تُضاف واجهة إنجليزية لاحقًا؟ (مؤجل P1 حاليًا.)
- هل يُبنى backend حقيقي للوحة التحكم في معلم لاحق، وبأي جدول زمني؟
- سياسة الاحتفاظ بسجل الطلبات المحلي (`localStorage`) وحد أقصى لعمره.
