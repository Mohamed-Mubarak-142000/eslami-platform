# PROD-004 — قواعد الثقة والحوكمة

## التوثيق

### تعريف تشغيلي

«عالم موثق» حساب تحققت الإدارة من هويته، ودليل علمي/مهني قابل للتحقق، وتخصصاته،
وصلته المؤسسية إن ادعاها. الشارة تثبت تحقق هذه البيانات وقت القرار؛ لا تعني العصمة
أو موافقة المنصة على كل رأي.

### الأدلة والقرار

- مطلوب: هوية، مؤهل أو إجازة/مسار علمي موثق، تخصصات، وسيلة تحقق مستقلة.
- اختياري: مؤسسة وروابط عامة؛ لا تظهر المؤسسة كموثقة دون دليل.
- الحالات: draft → pending → needs_info → pending أو approved/rejected.
- `approved` وحدها تمنح الشارة بعد تأكيد الخادم. لا شراء ولا self-approval.
- كل قرار: actor، timestamp، reason code، ملاحظة مهنية، version، وأثر تدقيق append-only.
- يسحب/يعلق التوثيق عند انتحال مثبت، دليل مزور، فقد شرط جوهري، أو مخالفة جسيمة وفق
  سياسة معتمدة. السحب قرار admin مسبب، ويمنع إجابات جديدة فور تأكيده.
- **مطلوب اعتماد:** قائمة الأدلة حسب البلد/المسار، مدة المراجعة، الاستئناف، وإعادة التقديم.

## الخصوصية والاحتفاظ

- السؤال `public`: النص والإجابات قابلان للفهرسة؛ إخفاء اسم السائل خيار مستقل.
- السؤال `private`: يراه السائل والمكلفون فقط، غير قابل للمشاركة العامة أو الفهرسة.
- قبل الإرسال تعرض الواجهة ملخص الجمهور الذي سيرى السؤال وتحذير عدم إدخال بيانات
  تعريفية غير لازمة. تغيير private إلى public يحتاج موافقة صريحة جديدة؛ العكس متاح
  ما لم تمنع حالة الإجابة ذلك وتوضح الواجهة السبب.
- وثائق التوثيق `restricted`: روابط مؤقتة، لا تظهر في logs أو previews أو notifications.
- analytics تستخدم IDs عشوائية وخصائص تعداد فقط؛ تمنع النص الحر، أسماء الملفات،
  الاستعلام الخاص، البريد، الهاتف، والهوية.
- عند الحذف تعرض الواجهة ما سيحذف/يجهل وما يلزم الاحتفاظ به قانونيًا.
- **مطلوب اعتماد قانوني قبل الإنتاج:** مدد الاحتفاظ، التصدير/الحذف، مواقع التخزين،
  ومن يستطيع كشف هوية السائل ولأي ضرورة.

## الإشراف

### أسباب البلاغ

`misinformation`, `hate`, `extremism`, `impersonation`, `harassment`, `spam`, `privacy`,
`other`. يتطلب `other` وصفًا؛ الوصف لا يدخل analytics.

### دورة البلاغ

open → triaged → in_review → actioned/dismissed → appealed (إن اعتمد) → closed.

- البلاغ لا يحذف المحتوى آليًا. يمكن تقييد الظهور مؤقتًا فقط وفق rule واضح عالي الخطورة.
- المراجع يرى المحتوى والسياق الضروري وتاريخ الإجراءات، لا بيانات المبلّغ إلا لضرورة.
- القرارات: no_action، label، limit_visibility، remove، suspend؛ كل قرار مسبب.
- نفس المراجع لا يحسم استئناف قراره إن توفر مراجع آخر (**مطلوب اعتماد تشغيلي**).
- أخطاء الشبكة لا تظهر نجاحًا؛ تعارض version يعيد تحميل الحالة دون فقد مسودة السبب.

## الخلاف الديني والمصادر

- المنتج لا يختار رأيًا «فائزًا» بعدد helpful أو الحداثة أو الشعبية.
- `recognized_disagreement` وسم تحريري يفعله مخول بعد تحقق: وجود أكثر من قول منسوب
  إلى مصادر وأصحاب مؤهلين، واعتباره ضمن نطاق السياسة الشرعية المعتمدة.
- كل Opinion تعرض: label وصاحب الرأي/المنهج عند الصلة، summary محايد، أدلة منظمة،
  حدود التطبيق، آخر مراجعة. ترتيب الآراء تحريري ثابت وقابل للتفسير.
- لا تدمج الواجهة الأقوال ولا تولد خلاصة حكم جديدة. يمكنها عرض «توجد آراء متعددة».
- كل Answer تحتاج عالمًا موثقًا، تخصصًا معتمدًا، مصدرًا منظمًا واحدًا على الأقل، تاريخ
  النشر/التحديث، وحالة review. الروابط وحدها لا تكفي: يلزم عنوان ونوع ومرجع.
- helpful يقيس فائدة العرض ولا يثبت صحة الحكم ولا يرفع العالم في ترتيب ثقة.
- **مطلوب اعتماد شرعي/تحريري:** الجهة المخولة، taxonomy المناهج، الحد الأدنى للمصدر،
  متى تسمى الإجابة «فتوى»، وسياسة المسائل الشخصية عالية الخطورة.

## نبرة الواجهة

- دقيقة وهادئة: «إجابة موثقة المصادر» لا «الإجابة الصحيحة الوحيدة».
- تشرح حدود الشارة والخلاف والخصوصية بلغة قصيرة قابلة للوصول.
- لا تستخدم اللون وحده للحالة، ولا عدادات تفاعل تحفز الاستقطاب.
