# PROD-003 — قصص المستخدم ومتطلبات P0

صيغة Given/When/Then هي عقد قبول. `GEN-01`: لكل شاشة الحالات المشتركة في نموذج المجال،
مع RTL وkeyboard focus واضح ونص حالة لا يعتمد على اللون.

## CAP-AUTH — الدخول والتهيئة

### US-AUTH-01 — التسجيل والدخول والاستعادة

كمستخدم أريد إنشاء حساب والدخول واستعادة كلمة المرور لأصل إلى ميزاتي الخاصة.

- Given بيانات صالحة، when يرسل النموذج، then تظهر نتيجة مؤكدة من الخادم ويعاد المستخدم
  للمسار المقصود أو onboarding.
- Given خطأ حقول/اعتماد/شبكة، then يظهر قرب سببه دون كشف هل بريد غير مسجل، وتحفظ الحقول
  غير الحساسة؛ لا تحفظ كلمة المرور.
- Edge: session منتهية أثناء mutation تعيد تسجيل الدخول ثم تطلب إعادة الإجراء، ولا تدعي نجاحه.

### US-AUTH-02 — onboarding قابل للاستكمال

- Given عضو جديد، then يختار بيانات أساسية وموضوعًا واحدًا على الأقل، ويمكن تخطي متابعة العلماء.
- Given انقطاع/خروج، when يعود، then يستأنف آخر خطوة محفوظة ويستطيع الرجوع وتعديلها.
- Then بعد الاكتمال يفتح Feed «لك»؛ غياب اقتراحات العلماء لا يمنع الإكمال.

## CAP-FEED / CAP-CONTENT / CAP-SAVE

### US-FEED-01 — تصفح feed

- تعرض «لك/تتابعهم/الأحدث»؛ تبويب المتابعة الفارغ يقترح Explore، والأحدث ترتيب زمني.
- pagination لا يكرر IDs، ويحفظ التبويب والموضع عند فتح محتوى ثم الرجوع.
- Edge: guest يرى محتوى عامًا وCTA للدخول عند تفاعل؛ offline يعرض cached معلّمًا إن وجد.

### US-CONTENT-01 — فهم أصل المعرفة

- تعرض التفاصيل النوع والمؤلف وحالة توثيقه وتخصصه والمصادر والنشر وآخر تحديث.
- فتح المصدر يوضح عنوانه ونوعه ومرجعه؛ الرابط غير المتاح لا يخفي بيانات المرجع.
- المحتوى hidden/removed لا يعرض body ويظهر سببًا عامًا ومسار رجوع.

### US-CONTENT-02 — تفاعل منضبط

- عضو يستطيع follow/helpful/save/share/report، وكل toggle يمنع التكرار ويصحح نفسه عند فشل الخادم.
- share لمورد عام فقط؛ مورد خاص لا يولد رابطًا عامًا.
- helpful لا يعرض كتقييم صحة أو ترتيب عالم.

### US-SAVE-01 — المجموعات

- أول save يستخدم «المحفوظات» أو يتيح مجموعة؛ الاسم 1–60 حرفًا، فريد للمالك بعد trim.
- يستطيع النقل/الإزالة؛ حذف مجموعة يؤكد ولا يحذف الأصل، ويعرض تعارض المورد المحذوف/الممنوع.

## CAP-EXPLORE / CAP-SEARCH / CAP-PROFILE

### US-EXP-01 — الاستكشاف

- تعرض أقسام موضوعات وعلماء وأسئلة عامة رائجة ومحتوى حديث مع عنوان واضح لكل نوع.
- لا يظهر سؤال خاص أو محتوى غير منشور؛ القسم الفارغ يختفي أو يعرض بديلًا مفهومًا.

### US-SEARCH-01 — البحث القابل للمشاركة

- الاستعلام والفلاتر type/specialty/topic/date/language في URL، وفتح الرابط يعيد نفس الحالة.
- النتائج مبوبة Answers/Scholars/Articles/Topics مع count أو دلالة توفر دون خلط الأنواع.
- zero results يقترح إزالة فلتر/تصحيحًا ومسار Ask؛ الاقتراح لا يرسل السؤال تلقائيًا.
- Edge: query فارغ يعرض recent searches محلية قابلة للمسح؛ private text لا يحفظ فيها.

### US-PROFILE-01 — ملف العالم

- يعرض الاسم والنبذة والتخصص والمؤهلات وحالة الشارة وشرح معناها وآخر تحديث ومحتواه العام.
- الشارة لا تظهر لحالة غير approved؛ suspended/revoked تعرض وصفًا غير تشهيري وفق قرار الإدارة.
- المؤسسة غير المتحقق منها لا تعرض كعلامة ثقة؛ follow يتطلب الدخول.

## CAP-QA

### US-QA-01 — إنشاء سؤال

- wizard: عنوان 10–160، تفاصيل 20–5000، topic، specialty، public/private، anonymity، مراجعة وموافقة.
- بعد العنوان تعرض نتائج عامة مشابهة؛ فتحها لا يفقد المسودة، ويمكن متابعة السؤال.
- شاشة المراجعة تذكر من سيرى النص. private افتراضيًا غير قابل للفهرسة أو المشاركة.
- Edge: double submit ينشئ سؤالًا واحدًا؛ فشل moderation أو الشبكة يبقي المسودة وحالة واضحة.

### US-QA-02 — تتبع السؤال

- «أسئلتي» تعرض pending_moderation/routed/answered/rejected/closed مع timestamp وسبب عام للرفض.
- تغير الحالة أو أول إجابة ينشئ notification؛ النقر يفتح المورد إن ظل مسموحًا وإلا حالة مناسبة.

### US-QA-03 — عرض السؤال والإجابات والخلاف

- السؤال العام يعرض إجابات منشورة بهوية/تخصص/مصادر/تحديث؛ إخفاء اسم السائل يحجب ربط ملفه.
- الخاص متاح فقط وفق matrix ولا يظهر في metadata أو share أو related content.
- عند recognized disagreement تعرض OpinionGroups بعناوين محايدة وأدلتها دون winner أو تصويت صحة.

### US-QA-04 — إجابة العالم

- verified scholar مكلف وضمن specialty ينشئ مسودة ويضيف مصدرًا منظمًا واحدًا على الأقل.
- member أو scholar غير approved/خارج التخصص يحصل 403 ولا يرى success حتى إن أظهر عميل معدل زرًا.
- عند تعليق التوثيق أثناء التحرير، يرفض النشر ويحفظ نسخة محلية آمنة ويشرح تغير الصلاحية.

## CAP-NOTIFY

### US-NOTIF-01 — مركز الإشعارات

- يعرض unread/read مجمعة زمنيًا، mark one/all read، وإعدادات أنواع داخل التطبيق.
- لا يتضمن preview لنص سؤال خاص أو وثيقة؛ المورد المحذوف يعطي رسالة عامة.
- optimistic read يعود لحالته عند الفشل؛ unread count نصي/معلن لقارئ الشاشة.

## CAP-VERIFY

### US-VER-01 — طلب التوثيق

- خطوات: هوية، مسار علمي، تخصص، مؤسسة/روابط، أدلة، مراجعة وconsent؛ draft محفوظ.
- upload يقبل الأنواع/الحجم المعرفة من الخادم ويعرض progress/cancel/retry، ولا يكشف اسم الملف خارج الطلب.
- لا يرسل ناقصًا؛ double submit idempotent؛ بعد pending يقفل الحقول إلا عند needs_info.

### US-VER-02 — متابعة ومراجعة الطلب

- المتقدم يرى timeline وسبب needs_info/rejection المهني والخطوة المطلوبة، لا ملاحظات داخلية.
- admin المكلف يرى الأدلة ويتخذ approve/reject/needs_info بسبب إجباري؛ كل قرار actor/time/version.
- 409 عند قرار متزامن يمنع overwrite ويعرض الحالة الأحدث. الشارة بعد approved من الخادم فقط.

## CAP-MOD / CAP-TAXONOMY

### US-MOD-01 — الإبلاغ

- العضو يختار سببًا، و`other` يتطلب وصفًا؛ تأكيد الاستلام لا يعد بالإزالة.
- تكرار نفس البلاغ النشط لا ينشئ duplicate؛ لا يرى المبلّغ هوية المراجع أو تفاصيل العقوبة.

### US-MOD-02 — معالجة البلاغ

- moderator المكلف يفلتر queue بالأولوية/النوع/الحالة، يرى السياق الضروري، ويسجل قرارًا مسببًا.
- remove/suspend تحتاج confirmation يذكر النطاق؛ restore مسبب؛ كل فعل يظهر في audit timeline.
- conflict 409 يحفظ مسودة السبب ويمنع قرارًا صامتًا فوق قرار أحدث.

### US-TAX-01 — إدارة التصنيف

- admin ينشئ/يعدل topic/specialty باسم فريد وحالة active؛ لا يحذف مستخدمًا دون بديل.
- moderator يقرأ taxonomy ولا يعدلها؛ تغييراتها تسجل وتظهر بأسماء وحالات لا بالألوان فقط.

## معايير شاملة للأمان والتحليلات

- لا PII أو نص حر أو اسم ملف في analytics/errors/URLs. الأحداث والخصائص في traceability فقط.
- كل mutation حساس يعرض pending ويمنع التكرار ويعالج 401/403/409/422/5xx/offline.
- fixtures الخاصة لا يعاد استخدامها في endpoint عام، واختبار سلبي يثبت غيابها من DOM وmetadata.
